# 操作与排错

## 统一入口

以下命令的 `python` 指当前机器可运行的 Python 3.12+；推荐 3.12。`<Skill>` 是实际安装目录，`<任务>` 是当前工作区内新建的任务目录，执行前替换占位符并对路径加引号。wrapper 使用已配置的隔离环境，无需手工设置 PYTHONPATH 或激活虚拟环境。

```text
python "<Skill>/scripts/runtime.py" --doctor
python "<Skill>/scripts/runtime.py" --tool preflight -- --manifest "<任务>/input.json" --work "<任务>/search-01" --workers 4
```

默认每首 QQ 优先，失败或无结果后网易云；预检只查元数据，不解析全量音频 URL。搜索目录必须全新或为空。先阅读 `search-01/review.json`，再依据 [清单格式](manifest.md) 创建 `confirmed.json`。有歧义时按 [版本选择交互](selection-ui.md) 调用含 `options` 的选择工具，每首一个问题，让用户点击后提交。结果会逐首写出，已确认项可先进入执行队列。

每首只要 QQ 返回任何候选，自动预检就可能停止该首的来源轮询。若这些候选均不匹配，智能体须明确指定网易再查，不能把“有候选”当成“版本正确”：

```text
python "<Skill>/scripts/runtime.py" --tool music -- search --metadata-only --query "歌名 作者 版本" --sources 网易云 --session "<任务>/search-extra.json" --timeout 20
```

QQ/网易都无合适结果时，先运行 `music sources` 读取支持的来源，再有针对性地搜索。其他来源不保证使用相同的轻量查询或 MP3 解析策略。最终音源仍须检查实际格式、时长、码率，并核对版本。

## 执行与发布

```text
python "<Skill>/scripts/runtime.py" --tool pipeline -- run --manifest "<任务>/confirmed.json" --work "<任务>/batch-01" --download-workers 1 --process-workers 1
python "<Skill>/scripts/runtime.py" --tool pipeline -- publish --manifest "<任务>/confirmed.json" --work "<任务>/batch-01" --out "<最终目录>"
```

`report.json` 中本次清单全部为 `verified` 才能整单发布。最终目录必须与工作目录分开，二者不能互相包含。不能将盘符根目录或用户主目录作为最终目录。若目标目录已有文件，先核对用户是否授权备份和替换；授权后 publish 可加 `--replace-confirmed`，旧内容保存在工作目录的独立备份中，最终目录只放本次 MP3。

不要将 `music download --out` 指向最终交付目录：该低层命令会写下载历史与报告，最终交付应通过 pipeline publish 完成。

## 时间预算与队列

| 环节 | 默认设置 |
|---|---|
| 同时预检歌曲 | 4，限本批进程；范围 1–15 仅用于受控测试 |
| 每首每来源元数据查询 | 20 秒，超时后尝试下一来源 |
| 指定 ID 解析 | 总上限 45 秒，含进程启动；较后接口不保证轮到 |
| 获取完整音源 | 逐首 1 个任务，每首总预算 300 秒 |
| 剪辑/编码处理 | 1 个任务，可与下一首下载重叠 |
| AI 分离 | 同时 1 首，默认最长 3600 秒 |

不能把 4 个搜索任务说成 4 个独立身份。多聊天或多批次不会拥有独立的平台限额，也不在本批限流器的全局保护范围内。

限流返回 429 时采用本批冷却；有 Retry-After 就遵守，没有则按内部默认值处理。已在途请求不会强制取消。超时或失败最多进行一次有依据的重试，优先让剩余歌曲继续；不要持续重启相同请求。

## 音源与质量

QQ/网易的 V3 解析按已配置的 320k MP3 路径优先；这些路径未成功时才考虑普通 FLAC（不高于 48 kHz、16 bit、2 声道）。采用有限音频头探测，完整下载后再读取实际格式、码率与时长，排除伪装扩展名和试听片段。

遇到 `quality_unavailable` 时，报告实际可用的低码率候选，请用户决定是否接受。当前默认脚本拒绝静默降级；用户同意后再明确处理降级路径，并在结果中说明源质量。不要通过改后缀、改标签或重复编码伪装原生 320k。

无裁剪且源为 CBR 320 kbps、44.1 kHz、双声道 MP3，采用复制；否则 FFmpeg 编码一次。任意起点/终点裁剪在成品开头加入 0.3 秒淡入。`end` 按原曲时间解释。

默认 `strict` 全部完整解码检查。`--validation balanced` 仅对成功严格转码的输出省略第二遍解码，不是忽略编码错误。保持 strict，除非用户明确要求调整检查策略。

脚本包含两种严格限定的容器恢复：FLAC 仅在完整 PCM 样本数和内嵌 MD5 一致时恢复；MP3 仅在可证明缺失区全部属于未使用末帧填充时补零。两者仍须通过严格解码。条件不足则失败，不能跳过损坏帧后宣布完整。

## 恢复与从头计时

同一批次再次运行可复用通过清单指纹、源/成品哈希和 V3 质量策略检查的结果。清单改变、音源改变或策略不符时重新处理。单首失败不会取消其他曲目。

用户要求从头计时：新建预检目录与执行目录，run 加 `--fresh`，不复用旧音源、搜索候选或成品。已有安装环境可以保留，但应单独说明是否计入首次环境准备时间。

报告记录解析、下载、分离、处理和校验耗时。整体实际时间与各曲耗时之和不同；搜索和用户等待也须另外记录。尚无跨歌单音源库，也没有 AI 模型常驻服务，不要声称已实现。

`.run.lock` 表示同一批次正在执行或上次异常退出。先查原进程是否仍存活，结束后才可处理残留锁。不得两个执行器同时操作同一目录。

## 本地验证

无需下载真实歌曲即可运行合成音频检查：

```text
python "<Skill>/scripts/runtime.py" --tool selftest -- --work "<任务>/synthetic-check"
```

完整离线测试用独立音乐环境的 Python 执行 `<Skill>/tests/run_tests.py`。准确 Python 路径从本机 `runtime.json` 获取。测试素材为合成音频；包内不含真实歌曲。

本版开发期间曾验证 QQ 的 3 个固定候选能取得实际 320k MP3，最终一轮获取与检查约 34 秒。它不含搜索选版、环境安装和开发时间，不能外推为每台机器或 15 首歌的耗时承诺。网易云有策略测试，但未做同等真实曲目速度对照。


## 已确认歌曲的有限补试（v3.1）

先读本批 report.json。只对本批失败、已确认的 QQ 候选使用一次补试；网易云及其他来源按现有下载入口处理。该工具将已选歌曲 ID 发给 lzmhhh 解析服务，逐首请求，延长短超时但不改变版本。不能把补试当成会员权限或可用性保证。

```text
python "<Skill>/scripts/runtime.py" --tool recover -- --manifest "<任务>/confirmed.json" --work "<任务>/batch-01" --ids "2,6" --out "<任务>/recovery-01"
```

补试目录与最终 MP3 目录分开。完成后读取其中的报告及 recover-manifest.json；成功项仅取得完整音源，仍须使用 pipeline run 进行处理与严格校验，再以同一份清单 publish。使用原批次工作目录、且未改动条目的清单指纹一致时，可保留本批已验证结果。原清单中的相对路径会规范为绝对路径；这种变化会让对应条目重新处理，因此首次确认清单优先保留预检生成的绝对会话路径。未完成项不能当作成功交付。

较低码率默认拒绝。仅在用户明确接受指定歌曲的源质量后，才可在首次补试命令加入 `--allow-low-bitrate-ids "2"`；结果须说明原码率。没有这项授权不要自动降级。只有低码率而未获授权时先反馈，再决定其他来源或新的质量选择，不能借此循环重试。429 时整个补试停止，按报告冷却；不要紧接着重开任务。

补试依赖当前候选会话（24 小时内）和原批次失败报告，不能对未确认曲目使用。失败原曲损坏时换同版本音源；包内仅保留既有的严格填充恢复范围，不把某一次特定文件的手工修复扩大成通用修复。
