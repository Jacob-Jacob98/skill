# 清单与确认

清单为 UTF-8 JSON，顶层含非空 `tracks` 数组。路径相对于清单文件所在目录；对机器生成的会话路径可直接保留其绝对路径，但不要把它们放入分享包。

预检输入见 [playlist.json](../examples/playlist.json)，它只是示例歌单，不是已确认下载任务。

| 字段 | 含义 |
|---|---|
| `index` | 原歌单顺序，唯一正整数，与搜索候选编号无关 |
| `stage` | 环节，必填字符串；用户没给时为 `""` |
| `title` | 歌名，必填 |
| `artists` | 完整作者列表；多位作者最终用空格连接 |
| `version` | 钢琴版、现场版、原版伴奏等；省略或空字符串表示未额外指定 |
| `start` | 原曲起点，秒数或 `分:秒` / `时:分:秒`；默认 0 |
| `end` | 可选，原曲终点，非保留时长；必须大于起点且不超出音源 |
| `query` | 可选，搜索关键词。特别版本可显式写歌曲加钢琴/伴奏等关键词 |
| `confirmed` | 只有版本明确匹配或用户已选择时为 true |
| `session` | 实际预检产生的会话 JSON 路径 |
| `candidate_id` | 该会话内实际候选编号，不得编造或从旧会话借用 |
| `source_file` | 用户提供或已确认的完整本地音源，可替代 session/candidate_id |
| `separate` | true 表示用完整原曲做 AI 伴奏分离，现成伴奏为 false |

## 歌单时间标注

图片或文字歌单中的单个时间（包括歌名后括号内的时间）直接映射为原曲起播位置 `start`，省略 `end` 以保留到歌曲结束；无需再次确认时间含义。例如 `59秒` → `start: 59`，`1分48秒` 或 `1:48` → `start: 108`。未标时间时使用 `start: 0`。

用户明确写明播放时长时，按 `end = start + 时长` 换算；明确给出起止区间时分别写入 `start`、`end`。仍须检查时间不超出实际音源；标注无法辨认或时间越界时，只询问该具体问题。

预检会清除输入里的旧确认及旧音源关联，生成 `manifest.pending.json`。不要修改正在更新的 pending 文件；把就绪条目复制到独立 `confirmed.json` 后写入实际候选 ID 与 `confirmed:true`。原清单其余字段和顺序保留。

确认后的在线条目必须有 `session` 与 `candidate_id`。本地音源条目用 `source_file`，不要同时保留旧在线候选。示例：

```json
{
  "tracks": [
    {
      "index": 1,
      "stage": "交换戒指",
      "title": "用户提供的音乐",
      "artists": ["已核实作者"],
      "start": "00:20",
      "confirmed": true,
      "source_file": "原始音乐/完整原曲.mp3",
      "separate": false
    }
  ]
}
```

上述本地文件名是结构示意，必须换成真实文件。不能使用已经裁剪过的成品再次按原曲起点裁剪。

版本有歧义时按 [版本选择交互](selection-ui.md) 为每首歌提供独立的可点击选项，列出作者、专辑、时长和平台，并明确是否试听过。用户实际提交后才确认；不用“1A、5B”这种手动编号回复。钢琴翻奏保留作品作者信息时，也应注明已确认的演奏者；没有可靠信息就如实说明，不把作曲者写成演奏者。

文件名由脚本生成，例：`1-交换戒指《1000x》Jarryd James BROODS.mp3`。起点时间不进入文件名。版本中的“AI分离”由 `separate:true` 自动加入；不要将 AI 结果冒充官方伴奏。
